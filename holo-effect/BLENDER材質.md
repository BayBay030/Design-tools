## 網頁的「滑鼠位置」在 3D 裡是什麼

網頁版靠滑鼠位置餵 `--fx` / `--fy` / `--fc` 三個數字，整個效果都跟著它們動。

3D 裡沒有滑鼠 —— 對應的東西是**看的角度**。所以 `HOLO_視角驅動` 做的事是：

1. 取 `Geometry → Incoming`（從表面指向觀察者的方向）
2. 用 `Vector Transform` 轉到**物件座標**、正規化
3. X / Y 分量壓成 0~1 → 就是 `fx` / `fy`（吃 `視角靈敏`）
4. `Layer Weight → Facing` → 就是 `fc`（正對 = 0，邊緣掠射 = 1）
5. **`視差X` / `視差Y` = `V.x / V.z`、`V.y / V.z`** —— 標準視差公式

所以**轉鏡頭 = 網頁裡移動滑鼠**。物件轉動也算。

`視角靈敏`（預設 3）調大，角度一點點變化就會掃很多顏色。

### 視差那兩個輸出在幹嘛

`fx` / `fy` 只夠拿來換顏色。要做出**深度**（各層錯開）必須用 `視差X` / `視差Y`：

把觀察向量除以它的 Z 分量，得到的就是「這個角度下，位在深度 1 的東西該偏移多少」。
乘上各層自己的深度值，各層就會用不同速度滑動 —— 這是真的視差，不是假的位移。

對**平面**（卡牌、貼紙）這個公式是精確的：平面的物件座標法線就是 +Z。
球面上不是精確解，但看起來也對。

## 幾個要知道的事

- **三個材質都吃 UV**。丟到自己的模型上要先展 UV，不然圖案會亂。
  預覽球是 UV 球，所以兩極會擠在一起，那是球的 UV 天生如此，不是材質壞了。
  貼在平面／卡牌上就是正的。

- **為什麼加了自發光**：金屬材質在沒有環境光的場景幾乎什麼都反射不到（第一版整顆黑）。
  網頁版的閃光本來就是「加亮」邏輯而不是物理金屬，所以這裡用自發光去對應，比較像。
  你的場景如果有 HDRI，可以把自發光調低、Metallic 調高，會更真實。

- **色相環不要用 ColorRamp 的 HSV 模式配同色兩端**。兩端都是紅色時它不會掃一圈，
  會整片停在紅色（第一版就是這樣）。現在用的是明確 13 段 RGB 色階。

- **第一版轉鏡頭幾乎看不出變化**，原因有兩個，缺一不可：
  ① 視角反應幅度給太保守（`視角靈敏` 原本 1、色相掃幅不到 1），轉三十度只掃過一點點顏色；
  ② 碎閃的「景深」是拿 `fx-0.5` 當位移，那個值最多 ±0.5，換算成格子只有半格，看不出層次。
  改成用標準視差公式 `V.xy / V.z` 之後，各層才真的會用不同速度滑動。
  **要看深度就轉鏡頭轉大一點，或把 `景深錯位` 拉高。**

- **⚠️ 改 `HOLO_視角驅動` 的介面 socket 會炸掉另外三個群組。**
  刪掉再重建輸入／輸出 socket 之後：
  ① 其他群組裡連到它的線**全部會斷**（而且不會有任何錯誤訊息）；
  ② 那些群組節點的 `視角靈敏` 會被**重設成 0**，等於整個視角驅動失效，
     畫面看起來正常、就是完全不會動。
  這兩件事我都踩過。要改介面的話，改完務必回頭檢查那三個群組的連線和靈敏度。

- **搬到別的檔案**：`File → Append → NodeTree`，把 `HOLO_*` 四個群組一起拿走
  （`HOLO_視角驅動` 是另外三個的相依，不能漏）。

## 跟網頁版對照

| | 網頁 | Blender |
|---|---|---|
| 驅動 | 滑鼠位置 | 視角方向 |
| 放射 CD | `repeating-conic-gradient` | `arctan2` + 色階 |
| 方格 | `background-size` 平鋪 | UV × 密度 → `fract` |
| 星星 | 內嵌 SVG 平鋪 | Voronoi 找格心 + `\|x\|^p + \|y\|^p` 畫四角星 |
| 景深 | 各層不同 `background-position` | 各層不同的 UV 偏移量 |
| 銀塊遮罩 | `mask-image` conic 十字 | `(u-.5)*(v-.5) < 0` |
| 疊圖 | `mix-blend-mode` | Mix 節點 / `MAXIMUM` |
